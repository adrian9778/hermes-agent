## 一、本模块目标

补齐工具系统全貌：

- 工具注册表（`tools/registry.py` · `ToolRegistry`）；
- 工具发现（AST 扫描 + 磁盘缓存，含「哪些文件才被扫描」的判定规则）；
- 工具 schema（动态改写与净化）；
- 工具调用分发（`model_tools.py` · `handle_function_call`）；
- 工具集与核心工具（`toolsets.py` · `TOOLSETS` / `_HERMES_CORE_TOOLS`）；
- 权限/审批（`tools/approval*.py` 族：门控、检测、智能审批、网关等待）；
- 环境隔离（`tools/environments/` · `BaseEnvironment`，7 种后端）；
- 错误体截断与清洗（`_MAX_TOOL_ERROR_CHARS` / `_sanitize_tool_error`）；
- 工具搜索渐进披露（`tools/tool_search.py` 桥三件套）；
- 连接器批处理（`tools/connectors/dispatch.py`）；
- 托管策略（`tools/hosted_tool_policy.py` 白名单）。

### 3.3 `register()` 参数（当前签名）

```python
ToolRegistry.register(
    self, name: str, toolset: str, schema: dict, handler: Callable,
    check_fn: Callable | None = None, requires_env: list | None = None, is_async: bool = False,
    description: str = "", emoji: str = "", max_result_size_chars: float | None = None,
    dynamic_schema_overrides: Callable | None = None, override: bool = False,
    scope: Optional[str] = None, execution_timeout: float | None = None,
    compat_args: Iterable[str] = (), self_checked_args: Iterable[str] = (),
    deadline_floor: Callable | None = None):
```

- `scope`：profile 覆盖槽。`None` 走进程级全局表 `_tools`；非 `None` 进该 profile 的 `_scoped_tools` 覆盖层。插件注册时若 `scope` 为 `None` 且能识别出插件归属，会自动落到该插件所在 profile 的槽（`ToolRegistry.register +849` 内部）。
- `dynamic_schema_overrides`：零参可调用，每次 `get_definitions()` 把返回的 dict 浅合并进 schema（例如 `delegate_task` 的描述要反映当前并发上限）。
- `execution_timeout`：handler 执行超时（秒），用于 connector 批处理的 per-call 预算。
- `compat_args` / `self_checked_args`：参数兼容性声明，供 `tools/arg_validation.py` 做更精细的拒绝。
- `deadline_floor`：可调用，返回该工具调用可 legitimately block 的最短时间（秒），用于 connector 批处理的 deadline 计算。
- **schema 在注册时就被校验**：`schema` 必须是 dict，`schema["parameters"]` 若存在必须是对象，否则直接抛 `ValueError`。这是刻意的——非法 schema 会序列化进每一次 provider 请求并在离现场很远的地方 400。

### 3.4 注册冲突规则

- **同 toolset 内同名重复注册**：允许，静默覆盖（MCP 重连/刷新依赖这条）。
- **跨 toolset shadow**：默认**拒绝**，只记 `logger.error` 并 return，不抛异常；确需替换必须显式传 `override=True`。
- **插件 shadow 进程级全局工具**：没有 `override=True` 直接拒绝并记 error。
- **插件 `override=True`**：还额外受 operator 配置门控 `plugins.entries.<plugin_id>.allow_tool_override: true`；未放行时抛 `PermissionError`。
- 插件的「归属」绑定在 handler 的**定义模块**上（`handler.__globals__["__name__"]`，`ToolRegistry._plugin_owner_of +765`），随包装器/`partial`/`__wrapped__` 解析，因此插件无法用回调洗白一次覆盖。
- 反注册同样门控：插件不能反注册不属于自己的工具（否则可先删后占空位绕过覆盖检查）；`mcp-*` toolset 例外。

### 4.2 流程

```mermaid
sequenceDiagram
    participant MT as model_tools.py
    participant REG as tools/registry.py
    participant AST as AST 扫描 + 磁盘判定缓存
    participant MOD as tools/*.py

    MT->>REG: discover_builtin_tools()
    REG->>REG: 枚举候选（tools/*.py + 两个包入口）
    REG->>AST: 按 (mtime_ns, size) 查缓存；缺失才 ast.parse
    AST-->>REG: 该文件是否在模块体调用 registry.register()
    REG->>MOD: importlib.import_module(命中的模块)
    MOD->>REG: registry.register(...)
    REG-->>MT: 已导入模块名列表
    MT->>MT: discover_plugins()（插件工具，失败仅 debug）
    MT->>REG: get_tool_definitions(enabled_toolsets, disabled_toolsets)
    REG-->>MT: 过 check_fn 的 schema 列表
```

判定规则（都来自源码，不是约定）：

1. **候选集**：扁平 `tools/*.py` 加上各包的一层入口模块（每个包只取那一个入口文件 `tools/<pkg>/tool.py`），合并后统一排序（`_tool_module_candidates +112`）。包内**只扫入口文件**，所以同包其余文件天然是库文件。
2. **硬跳过**：包初始化文件、`tools/registry.py`、`tools/mcp_tool.py` 不参与（后者由 MCP 发现流程单独导入）。
3. **必须真的注册**：只有**模块体**（含模块级 `for` 循环）里出现 `registry.register(...)` 的文件才会被 import（`_module_registers_tools +94`）。表驱动模块在一个 `for` 里批量注册，同样算命中。
4. **包必须有包初始化文件**：缺了会 `logger.warning` 跳过——否则 checkout 里能注册、装进 wheel 后消失。
5. **判定结果有磁盘缓存**：落在 `get_hermes_home()` 的 `cache/` 子目录下（`tools/registry.py` · `_discovery_cache_path +178`），键是绝对路径，值是 `[mtime_ns, size, registers]`；缓存不一致或损坏只重扫该文件。源码注释给出的量级是「逐文件 AST 扫描约 145 ms / 约 100 个文件」，所以缓存是启动时间的关键。
6. **插件工具**：`model_tools.py` 在 import 期调用 `hermes_cli/plugins.py` · `discover_plugins +0`，插件经 `ctx.register_tool()` 注册（见 [09-技能系统与插件架构](./09-技能系统与插件架构.md)）。
7. **MCP 发现刻意不在这里**：`discover_mcp_tools()` 内部会阻塞等待最长 120 s，而 gateway 是在事件循环里懒加载 `model_tools` 的，因此它被移出模块级副作用，由各入口（`gateway/run.py`、`cli.py`、`tui_gateway`、`acp_adapter`）在启动时各自触发。
8. **Safe Worker 策略**：`safe_worker_enabled()` 为真时（故障排查 worker），只导入三个核心模块（`tools.file_tools`、`tools.terminal_tool`、`tools.process_registry`），跳过插件/发现缓存（`discover_builtin_tools +121` 内部）。

### 5.3 错误体截断与清洗

- 工具错误返回模型前截断到 **2048** 字符（`_MAX_TOOL_ERROR_CHARS`），截断标记 `… [truncated]`；
- 日志保留更长信息（`_MAX_LOGGED_ERROR_CHARS = 8192`）；
- 关键补强：handler 里直接 `json.dumps({"error": str(exc)})` 会绕过 `tool_error` 的上限，因此派发边界上还有一层 `_bound_json_error_result +67`，把 JSON 结果里超长的 `error` 字段单独裁掉——防止失败重试时错误体层层堆叠；
- `model_tools.py` · `_sanitize_tool_error +657` 另做结构性清洗：剥掉 `</tool_call>` / `</function_call>` / `<![CDATA[...]]>` / 代码围栏，加 `[TOOL_ERROR]` 前缀，并复用**同一个** 2048 上限（保证文本不会经过两个不同上限、带两种不同标记）；
- `_TOOL_ERROR_STRIP_RES +649`：四条正则，分别 stripping XML-like tags、code fences、CDATA；
- 目的：防止工具错误污染 prompt 与 token 成本。

### 5.4 托管策略（Hosted Tool Policy）

- `tools/hosted_tool_policy.py` · `hosted_tool_refusal +83`：在托管作用域（`hosted_scope() is not None`）内，只允许白名单工具运行；
- `HOSTED_TOOL_ALLOWLIST +38`：`terminal`、`process_manage`、`execute_code`、`read_file`、`write_file`、`patch`、`search_files`；

### 6.3 门控方式

- **`check_fn`（可用性门控，profile 维度缓存）**：
  - 语义**仍然成立且被加强**：`tools/registry.py` · `_check_fn_cached +481` 仍是「TTL 缓存 + 单次装配内去重」；

  - 观察者不会把 entry 折叠到 wrapper 或兄弟 entry；
  - `is_interrupted()` 每 call 前检查，`/stop` 可阻止未开始的远程副作用；
  - `MAX_CALLS_PER_DISPATCH` 超限返回错误；
  - local calls 返回错误（`local_batch_error`）；
  - remote calls 逐 call 执行，结果合并。

### 10.4 连接器工具名格式

- `connectors__<connector>__<tool>`：连接器工具名格式；
- `tools/connectors/gateway/names.py` · `is_connector_name +35`：判断是否为连接器工具名；
- `tools/connectors/gateway/names.py` · `parse_connector_name`：解析连接器工具名。

## 十一、本模块结论

本模块补齐了工具注册、发现、分发、工具集、门控与环境隔离，并补上了两处上一版缺失的机制：**工具搜索渐进披露**与 **`toolset_distributions.py` 抽样分发**。**审批/权限控制**是本版重点扩写主题（58 文件族，覆盖硬线检测、智能审批、人类提示、网关审批、YOLO 模式、包装器变体）。后续模块继续展开配置、数据模型、技能/插件、调度、并发、错误、测试、部署和源码索引。
