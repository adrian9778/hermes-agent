## 一、本层目标

本层只做一件事：选一个**真实、最小、可跟读**的例子，把请求从用户输入一路追到最终响应，覆盖：

1. 前端/客户端入口；
2. CLI 参数解析与 Agent 装配；
3. 核心 Agent 循环；
4. LLM API 调用；
5. 工具调用分发（如果发生）；
6. 会话持久化；
7. 响应回到界面。

本层只走**主成功路径**。失败、重试、压缩、并发、插件钩子、缓存失效等细节先点到为止，不展开。

## 二、选择的最小例子

例子命令：

```bash
hermes -z "hello"
```

含义：以非交互方式启动 Hermes CLI，发送一条用户消息 `hello`，等待 Agent 完成并返回最终文本。

选择它的原因：

- 入口最短，不涉及 TUI、Electron、消息网关；
- 仍然经过真实 `AIAgent` 和真实 `agent/conversation_loop.py`；
- 能覆盖“用户输入 → CLI → Agent → LLM → 响应 → 落库”的完整主路径；
- 如果模型决定调用工具，还能自然展示 `model_tools.py:handle_function_call()` 与 `tools/registry.py` 的调用关系。

## 三、脱敏输入/输出

### 3.1 输入

```text
argv = ["hermes", "-z", "hello"]
user_message = "hello"
```

### 3.2 输出（示意，实际文本由模型决定）

```text
Hello! I'm Hermes, your personal AI agent. What would you like to work on?
```

### 3.3 关键副作用

- 在 `~/.hermes/state.db` 的 `sessions` / `messages` 表中新增或更新会话记录；
- 在 `~/.hermes/logs/agent.log` 中写入 INFO 级运行日志；
- 如果发生工具调用，工具结果会作为 `tool` 消息追加到本轮消息列表。

```mermaid

    participant AGENT as run_agent.py:AIAgent
    participant LOOP as agent/conversation_loop.py
    participant LLM as LLM API
    participant TOOLS as model_tools.py + tools/registry.py
    participant DB as hermes_state.py:SessionDB

    U->>MAIN: hermes -z "hello"
    MAIN->>MAIN: main() 启动自愈/环境准备
    MAIN->>PARSER: build_top_level_parser()
    PARSER-->>MAIN: parser + chat_parser
    MAIN->>MAIN: chat_parser.set_defaults(func=cmd_chat)
    MAIN->>MAIN: args.func(args) → cmd_chat(args)
    MAIN->>CLI: 构造 HermesCLI / 进入 chat 路径
    CLI->>AGENT: _init_agent() 装配 AIAgent
    CLI->>AGENT: run_conversation(user_message="hello")
    AGENT->>LOOP: run_conversation(agent, user_message, ...)
    LOOP->>DB: 加载/创建会话与历史
    LOOP->>LLM: messages + tool_schemas
    LLM-->>LOOP: 文本流或 tool_calls
    opt 模型返回 tool_calls
        LOOP->>TOOLS: handle_function_call(name, args, task_id)
        TOOLS->>TOOLS: coerce_tool_args + registry 查表
        TOOLS-->>LOOP: JSON 工具结果
        LOOP->>LLM: 追加 assistant/tool 消息后再次调用
    end
    LOOP-->>AGENT: 最终响应 dict
    AGENT-->>CLI: 最终响应 dict
    CLI-->>U: 打印最终文本
    LOOP->>DB: append_message() 持久化消息
```

## 五、逐跳走读（只走主路径）

### 5.1 入口：`hermes_cli/main.py:main()`

真实符号：

- 文件：`hermes_cli/main.py`
- 函数：`main()`，约在 `13103` 行
- 作用：CLI 进程入口，做启动准备，然后构建 parser 并分发到子命令。

关键动作：

1. `_set_process_title()`：让进程在 `ps` 中显示为 `hermes`；
2. `_advertise_agent_env()`：让子进程和工具感知运行在 AI agent harness 下；
3. Windows 下配置 UTF-8 stdio；
4. 清理旧更新残留、扫描过期 bytecode、自愈半成品 venv；
5. 尝试 Termux fast launch / fast chat launch；
6. 调用 `build_top_level_parser()` 构建 parser；
7. `chat_parser.set_defaults(func=cmd_chat)`；
8. 最终调用 `args.func(args)`，进入 `cmd_chat(args)`。

### 5.2 参数解析：`hermes_cli/_parser.py:build_top_level_parser()`

真实符号：

- 文件：`hermes_cli/_parser.py`
- 函数：`build_top_level_parser()`，约在 `136` 行
- 作用：构建顶层 parser、subparsers 和 chat subparser。

对 `hermes -z "hello"` 来说，`-z` 是 chat 子命令的“一次性消息”参数，最终 `args.func` 被设置为 `cmd_chat`。

### 5.3 子命令入口：`hermes_cli/main.py:cmd_chat(args)`

真实符号：

- 文件：`hermes_cli/main.py`
- 函数：`cmd_chat(args)`，约在 `3125` 行
- 作用：解析 `--in`、`--resume`、`--continue`、安全模式、TUI 选择，然后进入 CLI 或 TUI 运行路径。

对最小例子，主路径是：

1. `_resolve_use_tui(args)` 判断是否使用 TUI；
2. `_apply_safe_mode(args)` 应用安全模式；
3. 没有 `--in`、`--resume`、`--continue` 时跳过会话恢复；
4. 进入 CLI 运行路径，构造 `HermesCLI` 并执行一次性消息。

### 5.4 CLI 编排器：`cli.py:HermesCLI`

真实符号：

- 文件：`cli.py`
- 类：`HermesCLI`，约在 `5049` 行
- 关键方法：
  - `load_cli_config()`，约在 `412` 行
  - `_init_agent()`，位于 `hermes_cli/cli_agent_setup_mixin.py`，约在 `339` 行
  - `chat()`，约在 `16421` 行
  - `process_command()`，约在 `12118` 行

主路径：

1. 加载 CLI 配置；
2. 初始化皮肤/显示；
3. 通过 `_init_agent()` 构造 `AIAgent`；
4. 对 `-z` 一次性消息，调用 Agent 的对话接口；
5. 将最终响应打印到终端。

### 5.5 Agent 门面：`run_agent.py:AIAgent.run_conversation()`

真实符号：

- 文件：`run_agent.py`
- 类：`AIAgent`，约在 `422` 行
- 方法：`run_conversation()`，约在 `8597` 行
- 方法：`chat()`，约在 `9077` 行

`AIAgent.run_conversation()` 是门面/转发器。它：

1. 生成或接收 `task_id`；
2. 组装 `task_context`；
3. 处理 relay turn id、durable turn lease 等跨进程串行化准备；
4. 导入并调用 `agent.conversation_loop.run_conversation()`；
5. 返回最终结果 dict。

### 5.6 真实对话循环：`agent/conversation_loop.py:run_conversation()`

真实符号：

- 文件：`agent/conversation_loop.py`
- 函数：`run_conversation()`，约在 `1834` 行
- 作用：执行完整对话循环，直到模型不再返回 `tool_calls` 或达到预算/中断条件。

主路径：

1. 处理 MoA 消息解码；
2. 清理上一轮压缩状态；
3. 取消可能仍在运行的 background review；
4. 刷新 `.env` 凭据；
5. 调用 `build_turn_context()` 做每轮 setup；
6. 组装 `messages` 和 `tool_schemas`；
7. 调用 LLM API；
8. 如果返回 `tool_calls`，逐个调用 `handle_function_call()`；
9. 将工具结果追加为 `tool` 消息；
10. 再次调用 LLM，直到得到最终文本；
11. 持久化消息并返回结果。

### 5.7 工具分发：`model_tools.py:handle_function_call()`

真实符号：

- 文件：`model_tools.py`
- 函数：`handle_function_call()`，约在 `1240` 行
- 作用：把模型请求的工具名和参数分发到注册表。

主路径：

1. `coerce_tool_args(function_name, function_args)` 把字符串参数按 schema 转成正确类型；
2. 处理 `tool_search` / `tool_describe` / `tool_call` 桥接工具；
3. 执行 pre-tool-call hook / middleware；
4. 在 `tools/registry.py` 的注册表中查找 handler；
5. 调用 handler；
6. 执行 post-tool-call hook；
7. 返回 JSON 字符串结果。

### 5.8 工具注册表：`tools/registry.py`

真实符号：

- 文件：`tools/registry.py`
- 常量：`_MAX_TOOL_ERROR_CHARS = 2048`，约在 `33` 行
- 函数：`discover_builtin_tools()`，约在 `111` 行
- 方法：`register()`，约在 `763` 行

主路径：

- 每个 `tools/*.py` 在 import 时调用 `registry.register()`；
- `register()` 保存 `ToolEntry`，包含 name、toolset、schema、handler、check_fn 等；
- `handle_function_call()` 通过注册表找到 handler 并执行。

### 5.9 会话持久化：`hermes_state.py:SessionDB`

真实符号：

- 文件：`hermes_state.py`
- 类：`SessionDB`，约在 `4385` 行
- 方法：`append_message()`，约在 `11059` 行
- 方法：`get_messages()`，约在 `11961` 行

主路径：

- 会话开始时读取历史；
- 每轮结束后调用 `append_message()` 写入 user/assistant/tool 消息；
- 消息按 SQLite AUTOINCREMENT `id` 排序；
- 默认只读取 `active=1` 的消息。

## 六、最小例子的“如果发生工具调用”分支

`hello` 通常不会触发工具调用。但为了说明全路径，这里给出一个同样真实的最小工具调用例子：

```bash
hermes -z "Run pwd and tell me the current directory"
```

此时主路径会多出：

```mermaid
sequenceDiagram
    participant LOOP as agent/conversation_loop.py
    participant MT as model_tools.py
    participant REG as tools/registry.py
    participant TOOL as tools/terminal.py 等具体工具

    LOOP->>MT: handle_function_call("terminal", {"command":"pwd"}, task_id)
    MT->>MT: coerce_tool_args("terminal", args)
    MT->>REG: 查找 terminal handler
    REG-->>MT: ToolEntry(handler=...)
    MT->>TOOL: handler(args, task_id=...)
    TOOL-->>MT: 工具结果
    MT-->>LOOP: JSON 字符串结果
```
